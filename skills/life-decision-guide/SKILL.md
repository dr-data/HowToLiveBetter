# 人生決策：按《高性價比人生指南》查了再答

## 這個 skill 幹什麼

有人問一件具體的人生事情該怎麼辦，先去《高性價比人生指南》裡把相關條目查出來，再按書裡的算賬方式排好序回答。

**沒查到就別答。** 回答裡的每個數字、每條法條、每個結論都要能指回某一條正文；指不回去，就直說書裡沒寫，可以給常識判斷，但要標明那是常識不是書裡的內容。不要憑記憶補數字、補 DOI、補法條條款號。

書把要換回的東西分成四樣：壽命、時間與精力、金錢、人身自由。**四樣分開算，不互相折算**——「總死亡率降 12%」和「每年省 500 元」不在一把尺子上。

## 第 0 步：先看要不要馬上停下

- **正在發生的急症**（倒地沒呼吸、大出血、火災、溺水、觸電、中毒、卒中或心梗的症狀）：先說打 120 / 119 和現場第一個動作，出處第 13 節，別先講性價比。
- **提到自殺念頭、活不下去**：先給全國心理援助熱線 12356，再按第 1 節和第 29 節裡的條目說，不做勸導式分析，不評價動機。
- **正在進行的法律程序**（已被傳喚、已被拘留、已被起訴）：先指第 8 節對應條目，並說明書只給通用口徑，個案要找律師。
- 其餘情況，照下面的步驟走。

## 第 1 步：把正文拿到手

**本地**：當前目錄或上級目錄裡有 `README.md` 和 `book/01-不要早死.md`，就是本地模式，直接读。

**遠程**：沒有就現取。整本 1.3 MB，淺克隆一次最省事，後面所有命令都能照常用：

```bash
git clone --depth 1 https://github.com/eternity4719/HowToLiveBetter.git "${TMPDIR:-/tmp}/hltb"
```

不能用 git 時按文件取（文件名裡的中文直接寫就行）：

```bash
curl -fsSL --compressed "https://raw.githubusercontent.com/eternity4719/HowToLiveBetter/main/book/02-不要慢慢死.md"
```

這兩條都走不通，就說明取不到正文，如實告訴用戶，不要憑印象複述書的內容。

## 第 2 步：定位到節

先挑 1 到 3 節：讀倉庫根目錄 `README.md` 裡「這本書想回答的問題」那張表（一節一行，寫明這一節回答什麼問題，並帶著 `book/` 下對應的文件名），按用戶問的事對上號。節的增刪都反映在那張表裡，這裡不另留一份清單。

節文件就在 `book/` 下，文件名自帶節號和節名，`ls book/` 也能看全。

長文在 `docs/`：结婚划不划算、家庭应急装备清单、做平台要办哪些证、遇到陌生人出事该不该停。

## 第 3 步：把條目撈出來

節文件最大的有 110 KB，別整篇讀，按關鍵詞撈。有 Grep / Read 這類工具就用工具，只有 shell 就用命令：

```bash
grep -rn '^### ' book/ | grep -E '關鍵詞1|關鍵詞2'        # 先看有哪些條目標題
grep -rn -B2 -A8 '關鍵詞' book/08-别把自己搭进去.md        # 正文裡搜，帶上下文
sed -n '/^### 16\. /,/^### 17\. /p' book/08-别把自己搭进去.md  # 按條號抽一整條
```

**抽出來的條目要整條讀完**，尤其是「備註」欄——適用人群、爭議、例外都寫在那裡，只讀標題會把條件丟掉。

一條長這樣：

```markdown
### 5. 把家裡的食鹽換成低鈉鹽（鉀鹽）
<!-- 成本標籤: 錢=少 時間=少 毅力=否 收益=中 口徑=死亡率 -->
- 成本：每袋貴幾元
- 說人話：……死亡的概率低約 12%……
- 收益：腦卒中降 14%，心血管事件降 13%，總死亡率降 12%
- 證據等級：A
- 來源：Neal B, et al. (2021). NEJM. https://doi.org/10.1056/NEJMoa2105675
- 備註：爭議。腎功能不全、正在吃保鉀利尿劑的人不要用。……
```

那行 HTML 註釋是給機器讀的成本標籤：錢 0/少/多、時間 少/中/多、毅力 否/些/是、收益 大/中/小、口徑 死亡率/金錢/時間/自由。少數條目末尾還有 `人群=`（懷孕、嬰幼兒、孩子、老人、35歲、60歲、女性，逗號是或、加號是且），表示只對這些人有用；用戶明顯不在那個人群裡時，這條可以不推薦。

## 第 4 步：排序

排序照書的算法，別憑感覺：

1. 檔位的算法以倉庫根目錄的 `index.html` 為準，別憑記憶寫，當場把那兩行摳出來照著算：

   ```bash
   grep -n 'COST_W = \|e\.ratio = ' index.html
   ```

   前一行是三項成本各檔的權重，成本分 = 錢 + 時間 + 毅力三項相加；後一行是收益量級配上成本分怎麼落到「極高 / 高 / 一般」。
2. 只按文件 curl 了正文、手上沒有 `index.html` 時，別報性價比檔，改成把收益量級和三個成本標籤原樣列出來，讓用戶自己掂量。
3. 先按性價比，同檔再按證據等級 A > B > C，再按跟用戶處境的貼合度。
4. **不同口徑之間不排序**。換錢的和換壽命的分開列，各排各的。
5. 「一般」不等於不該做，只是那筆花銷得用戶自己掂量。性價比是作者的判斷，按書自己的標準只算 C 級，和證據等級是兩回事。

## 第 5 步：怎麼寫這份答覆

排好序之後按這個結構寫：

1. **一句話結論**：這件事劃不划算、該不該做、第一步是什麼。
2. **先做這幾條**（3 到 7 條，按上面的序）。每條一行到三行：動作（動詞開頭）、花掉什麼、換回什麼、證據等級、出處寫成「第 8 節第 17 條（借條和擔保）」，括號裡的詞取自條目標題，方便用戶自己翻。
3. **別做 / 不用做的**：書裡明確說不值得或有反面證據的，單列出來。
4. **書裡沒寫的**：如實說，不要拿常識冒充書的內容。
5. 需要的話補一句複查點：什麼時候回頭再看一次，或者什麼信號出現就改主意。

寫的時候守住這幾條：

- **落到誰身上要說清**。書把受益人分四檔，按好處回到自己身上的可能性從高到低：① 你自己；② 配偶和直系親屬；③ 朋友、同事和其他親屬；④ 陌生人。寫到第 ④ 檔（救陌生人、替人擔保、幫人轉賬）要把風險面和好處一起寫：被訛、被捲進案子、被報復，不能只寫好處，也不能寫成一律別管。
- **「法律支持你」的事必須連過程成本一起說**。只說結果不說過程，等於把勝訴率當成收益。要交代要不要打官司、大概多久（一審普通程序 6 個月起、可延長，簡易程序 3 個月）、律師費誰掏（律師費不在訴訟費用裡，敗訴方負擔不包括它）。
- **數字照抄條目**，一個不改。條目裡寫了置信區間、人群、年份就一併留著；HR、RR、OR 這類寫法旁邊就地翻成「低約 28%」，原值不刪。條目裡沒有的數字、症狀、機制解讀一律不加。
- **口語化**：按沒受過專業訓練的成年人能一遍讀懂來寫。專業名詞當場用日常話解釋一句，法條落到「會攤上什麼後果、該怎麼做」。來源欄照原樣給，方便核對。
- **語氣剋制**，不說教，不用感嘆號，簡體中文。用戶不按建議做是他自己的事，不追著勸。
- **政策會變**：第 7、19、21、24、31、32 節裡那些金額、時限、名單，正文寫了截至日期，答覆裡把日期帶上並提醒用戶自查官方渠道。
- 有「爭議」標註的條目，把反方證據也說一句；標了「TODO 待核實」的，別當結論用。
- 不引知乎、公眾號、搜狐這類二手轉述，只給條目「來源」欄裡已有的鏈接。

## 邊界

這本書給的是通用口徑，不替代醫生、律師、會計。涉及具體病情、具體案件、具體稅務的，按書裡的條目給方向和該找誰，別替專業人士下判斷。不給個性化投資建議。

書的觀點是作者的，性價比檔怎麼劃也是作者的判斷。用戶不同意某一條時，把書裡的依據擺出來就夠了，不辯論。
